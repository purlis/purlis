### Security

- **The app's git no longer trusts what a chat writes in a worktree's git record.** Where a chat can write `.git/worktrees/<piece>/` (sandbox level off), a link planted as `COMMIT_EDITMSG`, `logs/HEAD`, `FETCH_HEAD`, `index` or any other file git writes there made the app's git write through it into a file you own, and the app's own `purlis-brokered-commit` note could be forged the same way. Before the app commits, updates or pushes in a branch folder it now refuses a record that holds a link or anything that is not a regular file or folder, the note lives in the app's own notes folder and is written through no link, and `purlis worktree update --continue` goes on only with the plan the update derives from its own record (an `exec` line, another commit's `pick` or an `update-refs` file added since is refused). A brokered commit, an update and a push are refused where `HEAD` names a branch other than the one the folder was cut for (#7553). The app's git now also refuses a pseudo-ref (`ORIG_HEAD`, `REBASE_HEAD`, `AUTO_MERGE`, any `*_HEAD`) that holds `ref: <name>`, which made a rebase move another branch, and holds `HEAD` to exactly `ref: refs/heads/<the branch the piece was cut for>`: that branch is now recorded by the app when the piece is cut, so a piece cut with `--branch` (`fix/…`, `prototype/…`) commits again and a folder named after another branch no longer passes. A piece cut before the record is noted from the branch it is on, where that branch is its folder's name or one the clone recorded a base for, and the app says so. `--continue` and `--abort` check the rebase's whole state (branch, starting commit, onto, author, plan) right before git runs, and the plan is derived from the range the app recorded when the update started instead of being copied from a file a chat can write. The app's git writes no reflog it did not find, and looks at the record again after it runs.

Not prevented: a link planted while git is running, a write to a rebase's plan between the app's last look and git reading it, and, with the sandbox off, a write to the app's own notes folder.
