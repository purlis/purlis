### Changed

- **Asks marks two more kinds of ask as high risk.** An ask that deletes (`rm`, `git branch -D`,
  `git push --delete`, or a harness's own delete of a file) and an ask that hands a credential
  from a purlis vault to a chat's program, a page or a pool's runner now say "High risk" and
  what they do on their row. They are never grouped, never offered as a rule, and their Allow
  asks once more before it acts, also where the ask is answered in its form. A `git push` that
  names no branch is now read by the branch the chat's folder would push, so a push from a chat
  on a protected branch is marked too. A run of a reviewed program with a vault's values is one
  of these, so it is no longer offered Always allow as a rule after the same Allow twice; its
  own Always allow is still among its answers.
