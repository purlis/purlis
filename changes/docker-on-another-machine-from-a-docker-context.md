### Added

- **A pool on another machine can start from one of your Docker contexts.** In Pool setup's Connect, your contexts are listed beside your SSH hosts: one reached over SSH under SSH, and one reached over Docker's API with TLS under that route, with its own certificates. Pick one, check the machine's key or CA, and trust it as usual. purlis reads the context once and keeps its address. Nothing it runs follows the context afterwards. A context on this machine's own Docker sets up a pool on this machine. If the context later points somewhere else, Connect says so and offers Connect again or Keep the pool as it is. When Docker here points at another machine, Where offers Set up Docker on another machine, with that machine filled in. From a terminal, `purlis pool add <name> --image … --context <name> --trust …` does the same (#6268).
