### Fixed

- **A chat that cannot use your own `gh` login now says why, and what to do.** Where a chat's sandbox holds your own credentials back, a `gh` call that failed on its own config read (`hosts.yml`) raised no Notice and told the chat nothing, so work stopped with no way on (#1349). A failed command's refusal of one of your credential files now raises the credentials Notice, naming the ways that work. A chat that starts with the credentials held back, a GitHub or GitLab remote in the project and no agent identity says so on its tab, with the way out: set up Agent identity in Settings › Agent identity, or choose a sandbox template where the credentials are not held back. The `gh` of a chat whose tool mints its token from an agent identity answers a chat with no token with that same sentence and exits, and never falls back to your own login.
