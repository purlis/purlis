### Fixed
- The app's own git (`purlis worktree update` and `push`, run for a chat) now refuses a worktree whose git record holds a name git acts on, in any letter case, and no longer looks at the rest. A rebase's `refs-to-delete`, a linked `MERGE_MODE`, a lower-case `orig_head` that names a branch, a `config.worktree`, a `sequencer/` and a non-empty `refs/` no longer move or overwrite anything, while the empty `glab-cli/` folder, `gc.log`, `modules/` and the other residue git and your tools leave in most records are ignored. A rebase's plan is continued only when it names whole commit ids, and the update's rebase copies no notes and reschedules no failed `exec`.
- A piece cut before purlis kept a note of its branch is noted when its `HEAD` is exactly the folder's own name and no other folder has that branch. For a piece cut with `--branch`, run `purlis worktree adopt <repo> <piece>` once from your own terminal to record the branch it is on. A cut that cannot note its branch fails.
