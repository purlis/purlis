### Changed

- The Organisation's policy folder (`/etc/purlis`, or `%ProgramData%\purlis` on Windows) is now checked for its owner and permissions before purlis trusts it, including a macOS ACL that lets someone else write. On Windows the owner and ACL reader is not written yet, so a folder that is there reads as strict with every lock. A folder that fails reads as strict with every lock, and the Notice names the failed check and how an administrator can fix it or remove the folder. `policy.json` is translated into the Organisation's rules and locks, and a process outside every project is held to them too. A wildcard or ported host in `policy.json` (`*.domain`, `host:port`) is matched as the host list matches it, and a `false` of `dispatch.allow`, `opt-out`, `persona-tools`, `vault-grants` or `live-asks` is a hard refusal, never an ask. A key written twice in `policy.json` makes the file broken.
