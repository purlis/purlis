### Security

- **Accept takes exactly what the window showed.** The press compares a digest of every family's
  mode, from the committed file at `HEAD`, your local file and the administrator's locks, read
  once. A change to any of them since the window showed it accepts nothing. Where git cannot read
  the project's last commit in time, `[policy]` runs as `strict` and the window says so.
- **A commit purlis makes for a sandboxed chat is scanned under the policy of the project the
  app holds the chat in**, never one found from the folder the commit is made in.
- **A chat cannot write its way into the enforcement log.** A line a chat's process hands over is
  kept only for an open chat of the project, a rule purlis has, and a `host:port`. Each chat's log
  stops at 10,000 lines.
- **A seal key purlis's app did not make is not trusted.** The app uses the key only once it has
  shown it owns the keychain item. Where another program owns it, every family is enforced and
  dispatches across personas are refused until you press Accept again. A sealed acceptance
  whose keychain anchor is gone now counts as broken too.
