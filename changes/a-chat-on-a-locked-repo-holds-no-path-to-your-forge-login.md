### Security

- **A chat on a repo that holds your credentials back, or that has a minted token, is handed less of your own forge login.** Its `gh` reads an empty config folder, its git runs with every credential helper emptied (the system's, yours, and a repository's own `.git/config` too) and never prompts, its ssh is told no agent where purlis sets it, `browser_login` to a forge host is refused, and a forge connector (`github`, `gitlab`, `claude_ai_GitHub`, `claude_ai_GitLab`, `gh`, `glab`, by name) is turned off in Claude Code, Codex and opencode while the rest of your MCP servers keep loading. This is not a lock yet: gh's macOS keychain token, git's own `osxkeychain` helper named on a command line, an ssh agent socket you granted, a bare `ssh` reading `~/.ssh/config` (and Claude Code's own ssh), and a claim made by a minted token alone stay reachable, so no harness version is reported as locked (#7205, #7133).
