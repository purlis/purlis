### Security

- **A chat's right to force-push a branch it created through the forge route now follows stable identities, and holds only from the tip it left.** The record of created branches is keyed by the plane's project id and the forge's own id of the repo (GitHub's numeric id, GitLab's project id), no longer by paths a person can reuse, and it keeps the tip of each push the forge confirmed. An update is let through only when its old id is the tip the chat last put on that branch, read from the record at every update: a branch deleted and created again (by a colleague, or by another chat through the route), pushed to by anyone else, or never advertised to the chat has another tip and is refused, whether or not the chat read the forge's advertisement. A repo deleted and created again at the same path, or another project at the same project path, owns none of the old records. Records written before this (no project id, repo id or readable tip) are owned by nobody; the person pushes those branches (#7363).
