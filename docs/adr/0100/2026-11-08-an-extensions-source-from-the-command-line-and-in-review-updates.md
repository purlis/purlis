# An extension's source from the command line, in Review updates and marked in Browse

**Amends [ADR 0100](../0100-a-skill-is-installed-from-a-git-source-as-a-pinned-copy-and-never-updates-by-itself.md), 2026-11-08**, ticket #5760. The amendment of the same day ([an extension's source installs what its review read](2026-11-08-an-extensions-source-installs-what-its-review-read.md)) left three things unbuilt. This records how each was built. Its rules hold for all three: the same review, the copy is the bytes that review read, the extension still approved and on, and nothing skips the person's consent.

**`purlis skill install --extension <id>` installs from an extension's source.** With no skill named, it lists what the source offers, each skill with what its files do and where it is installed. With names, or `--all`, it prints the same review the git source's install prints, asks once, and installs what that review read, pinned to the revision. The extension is asked through the executor's gate, as the studio asks it (ADR 0101), and only while it is a skill source here: approved on this machine, on in the project, declaring `skill-source`.

- **It is asked at the person's interactive terminal each time, and has no `--yes`.** The window's install from an extension has no way past its review, so the command line has none either. Standard input and standard error must both be a terminal: a script, a pipe or a detached process installs nothing.
- **A chat is refused, as for a git source.** It is told the sentence a git install from a chat is told. It is not proposed (#5472's rule): a proposed install is a new capability, and if it comes it comes for both kinds of source at once, by the operator's say.

**Review updates (#5354) holds an extension's skills.** Each one's review is asked through its extension, and the window holds what each read, as for one update. Accepting the set copies each skill's own held bytes inside the same single commit, all or nothing, with one Undo. The core (`update::set::Updating::held`) refuses the whole set if any held review is not at what was accepted, is another extension's, or is missing. The app refuses it if the extension is no longer approved or on. A skill that newly gains a script, hook, tool or network access starts unticked and is refused unless ticked, by the same rule as a git source's (operator's ruling of 2026-11-05). Each held review is let go of once the set is made. The window now holds the last 32 reviews read, not 8, so a page of updates fits.

**An extension's Browse marks what each skill's files do**, as a git source's page does ("runs a script", "reaches 1 host"). Browse asks the extension for each skill's files, the first 32 skills and up to the bytes one read of a git source may take. Past those, or where a skill's answer is refused, the skill says its files are read when it is reviewed. The marks only inform. What Browse read is let go of, and an install copies only what its own review read. Installed and Update available were already marked from the lockfile and the updates check.

**Not decided here.** Whether `skill-source` joins extension API version 1 amends that API's freeze (ADR 0101, amended 2026-11-02), and that is the operator's call.
