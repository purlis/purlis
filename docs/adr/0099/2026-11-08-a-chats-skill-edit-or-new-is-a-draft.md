# A chat's `purlis skill edit --from` or `skill new` is a draft in the Skill studio

**Amends [ADR 0099](../0099-a-skill-lives-at-a-level-a-project-skill-reaches-a-workspace-by-grant-and-the-narrowest-copy-wins.md), 2026-11-08**, ticket #5815. The amendment of 2026-10-21 said a chat's change becomes a draft the person accepts in the studio, but a chat's `purlis skill edit` was only refused, and no draft was made. Spec #2762's decisions 26 and 38 ask for the draft.

- **From a chat, `purlis skill edit <name> --from <file>` and `purlis skill new` leave a draft.** The command checks the text as it does at the person's terminal (`verbs::edit_checked`, `verbs::new_checked`). It then hands the app the new `SKILL.md` as `Ask::Propose`. That is the same ask a chat's `Write` to a skill's file or its `purlis propose` makes. The app keeps it in the Skill studio's Drafts (`skilldrafts::drafted`, `drafts::take`). The person reviews its diff there and accepts or declines it. Nothing in the skill's folder is written, and the command says which draft waits and where.
- **A text that is no whole skill, or that renames it, is refused as before, and no draft is made.** The same holds for a new skill whose name is taken or reserved, and for a text that changes nothing.
- **A chat that can't reach the app makes no draft and writes nothing.** That includes a chat with every environment mark stripped, which is still known as a chat by where it runs (#5357). It never falls back to saving the change itself.
- **Only the person accepts.** Accept and Decline are the window's alone. No `purlis` command accepts a draft, so a chat can't accept its own.
- **`rm` and `mv` of one skill are not drafts.** They are proposed to the person as a change to skills (#5357, `Ask::ProposeSkillSet`), because a draft holds a skill's files and these change where the files are. Every other writing `purlis skill` verb is still refused in a chat, and its message names the two commands that draft.
