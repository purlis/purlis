# On Linux, the level records are what keeps a later level's skills from chats

**Amends [ADR 0099](../0099-a-skill-lives-at-a-level-a-project-skill-reaches-a-workspace-by-grant-and-the-narrowest-copy-wins.md), 2026-11-09**, ticket #3097 (SK-41). The amendment of 2026-10-22 held every level's skills folder by a pattern with one any-name part (`workspaces/*/skills` and the like) beside the exact paths of the levels already there. It said that Claude Code's reading of a mid-path pattern in its Linux sandbox had not been measured, and that where a backend cannot hold a pattern, `skills::levels` is the guard.

- **Measured on Linux, 2026-11-09.** Claude Code 2.1.300 (the version in `tests/fixtures/harness-versions/claude.txt`) was run under its own sandbox (bubblewrap) on CI's Ubuntu 24.04 runner, in run 42542971103 of pull request #5901. It had the settings a start writes, and a stand-in model on a loopback port, so no model was called and no credential was used. The test is `a_workspace_made_after_a_claude_code_chat_starts_hands_no_chat_its_skills` in `crates/purlis-core/tests/it/claude_codes_own_sandbox_holds_the_settings_purlis_writes.rs`, run by the step "Claude Code's own sandbox on Linux, on the settings purlis writes". A level there at the chat's start stayed held by its exact path. The pattern did not hold a level made after the start.
- **So on Linux the level records are the guard.** A workspace or persona folder made while a sandboxed chat runs reaches no chat while that chat's record stands. After the chat closes, it waits for the person's Accept in the Skill studio (`skills::levels`, as built for SK-9). Two tests hold this:
  - The measurement test asserts that a level made during the chat gives no chat a skill, and that a level there at the start still does. It never fails on what the pattern held. Without the start's note of the levels, it fails.
  - `a_sandboxed_claude_code_start_leaves_a_workspace_made_while_it_runs_out_of_every_chat`, in `a_start_the_host_composes_runs_as_the_window_would_start_it.rs`, asserts that the host's composed start of a sandboxed Claude Code chat writes that note (`hoststart::compose_ready`).
- **macOS is unchanged.** There the pattern becomes a regular expression in Claude Code's profile and holds a later level too. The measurement test asserts that wherever CI's macOS step runs Claude Code.
- **The pattern stays in the settings purlis writes.** It costs nothing where it is not held, and it holds wherever a backend reads it: Claude Code on macOS, and purlis's own wrap on both systems.
