# Amended for #2590, a runner chat composed by its names is asked too, 2026-10-18

The amendment for #2510 gives a chat whose plan the window made a service the person allowed
for that chat alone, on the runner, once the person allows it there. This note does the same for a
harness chat the runner composes by its names (ADR 0078, amended 2026-10-18 for #2446), where the
window makes no plan. Everything in the amendment for #2510 stands as accepted, and item 3 there
stands as the operator ruled it on 2026-10-18: **the person is asked, per chat**. What follows is
**decided in implementation, to be confirmed** (D-2590-1 to D-2590-3).

1. **The window tells the runner which services it allowed the chat alone.** A start by its
   names that names its confinement may name them (`alone`, session protocol 1.26, a minor): the
   ports the chat's own plan on this machine gives with their loopback entries at the chat's
   layer and at no other, as the window plans such a service. Only the window, or its host
   relaying it, may send them, and only beside the confinement the runner composes for the chat,
   which asks the window. A start that names them anywhere else is malformed. *D-2590-1.*
2. **The runner leaves out each one its own sandbox does not give, and says so.** The
   confinement it composes for the chat gives what the runner's own sandbox for the project
   gives, as before, and nothing more. Each port the window named that this does not give is
   named in `confined.left_out`, with the runner's name, as for a plan made elsewhere, so the
   chat's tab says the runner left it out. *D-2590-2.*
3. **It is asked about, and answered, as item 3 of the amendment for #2510 says.** The runner
   takes an answer about one of its own loopback ports only for a port it left out of that
   confinement, and refuses any other in a sentence. Nothing is kept on either machine.
   *D-2590-3.*
