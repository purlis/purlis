# Amended 2026-11-08: a picked entry is one its persona may use

The person's ruling on #5246's adversarial review (D-5246-1), amending D-5080-11 (#5579) and
narrowing ADR 0109's "picking an existing entry writes a Linked entry".

D-5080-11 narrowed the entries a run's notice offers to those of a vault the persona may use, and
to none a browser login fills or a `mint` line marks, because a link is for good and every later
run reads through it. It left a plain Secret ask's picker as it was. A chat asking ahead with no
program, or naming one that isn't reviewed, then got the wider picker: steered, it could ask for
`DEPLOY_TOKEN` "from finance's `PROD_PW`", and the person's pick linked the persona's key into a
vault the persona may not use. A later Run grant's notice named only the persona's own vault and
key, and Allow handed finance's value on.

Both ends are closed:

- **The picker.** A plain Secret ask lists what a run's notice lists: entries of a vault the asking
  persona may use, and none no program is handed.
- **The press.** A Link is judged by the same rule in the core before anything is written, whatever
  the window listed. A Link into a vault the persona may not use is refused too, as a Fill there
  already was.
- **The gate.** A program a person allows is never handed a key that links into a vault its
  persona may not use, however and whenever that link was made, so links made before this ruling
  are covered. The chat hears why, without the other vault's name.

A declared tool is unchanged: it reads through a link as it always did.
