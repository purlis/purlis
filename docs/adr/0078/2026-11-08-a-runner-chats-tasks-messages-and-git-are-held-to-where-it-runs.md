# Amended 2026-11-08: a runner chat's tasks, messages and git are held to where it runs

It follows the 2026-10-30 note, which holds a runner chat's open or dispatch for the person's
Approve. **Ruled by the person, 2026-11-08:** each point below takes the option recommended to
them.

1. **What a chat on a pool's runner sends names its pool.** A follow-up, a follow-up to every
   task and an answer a runner chat sends a task on this machine, and a note, a question and a
   report a task on a pool's runner sends the chat that asked for it, say who they are from as
   `<chat> (on pool <pool>'s runner)`: the chat that reads them knows the words came from a
   runner. The pool is the link the line came over, else the router's record of the chat on a
   pool; a report's is the router's record of the chat that reports. The name is held to a
   chat name's 64 characters, the chat's own name cut, never the pool.
2. **A chat with tasks still working on this machine is not moved to a runner.** Move to runner
   is refused while the chat, or a chat of its workspace that would move with it, has a task
   still working here, in words saying how many and to end them or wait for their reports. The
   switch asks again, so a task dispatched after the move was asked for holds it too. Move here
   is not held.
3. **A launch starts no task a runner chat asked for.** A task still owing its report whose
   asking chat ran on a pool's runner (the pool its start chose, the pool this machine kept it
   on, or the pool its workspace or project runs its chats on) is not started again at a launch.
   It waits with the chats that did not start, drawn under the chat that asked, with **Try to
   start again** and **End task**, its dispatch still running. A task the session host kept
   running is not a start and comes back as it was.
4. **A pool's chats hold at most 8 together.** Beside the 8 one chat may have held, the chats of
   one pool together have at most 8 opens and dispatches waiting for the person. One more is
   refused in words naming the pool.
5. **A runner chat's git work is done on its runner.** A clone, branch folder, update, save or
   commit a chat on a pool's runner asks this machine for is refused in words naming the pool,
   decided as a runner write is: by the link the line came over, else the router's record of the
   chat on a pool. Nothing is made on the person's machine for it.
