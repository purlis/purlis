# Amended 2026-10-20: a forgotten project's window name goes, and a give-back is held to the policy

**Built by #2738** on the amendments of 2026-10-20 for #2623, #2625 and #2645. What follows was
decided in #2738 and is marked *decided in implementation, to be confirmed*.

1. **Forgetting a project lets go of its window name.** When the person forgets a project on
   this machine (You › This machine, or a gone project's Forget), the name its root's link kept
   in `window-names.json` is removed with it, and every other root's name is kept. A project
   opened again names its link anew and takes back no runner chat of the one forgotten. A file
   that holds no names is not written. A name that cannot be removed leaves the project
   forgotten all the same, and the app's log says so: the name then only ages out. *Decided in
   implementation, to be confirmed* (D-2738-1).
2. **A port given back after a re-link is held to the runner's policy as it is then.** Before
   the runner gives back a port it withdrew for want of a window, it asks its own sandbox for
   the project whether it gives a chat that service now, as a plan made elsewhere is held to it
   at its start: yours for the project on that machine, at a scope policy leaves open. One it
   no longer gives stays withdrawn, and the runner's log says why. It stays withdrawn for want
   of a window, not as the person's withdrawal, so a later re-link, once the policy gives it
   again, gives it back. *Decided in implementation, to be confirmed* (D-2738-2, D-2738-3).
3. **The standing "not held" mark waits for the runner screen.** Item 3 of the amendment for
   #2645 stands: until the window has a screen for its runners, a project a re-link could not
   hold shows only through the refusal of the next command that needs the hold. The mark is
   built with that screen. *Decided in implementation, to be confirmed* (D-2738-4).
