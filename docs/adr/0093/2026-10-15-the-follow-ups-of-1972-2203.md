# Amended 2026-10-15: a failed background command's output, and more readers (#2203, #2202)

Follows [printed text is never a block](2026-10-15-printed-text-is-never-a-block-1972.md).

- **A background command's output read back by file is read by how the command ended**, where
  Claude Code's own record says (#2203). When a background command ends, Claude Code writes a
  notification into the session's transcript naming its output file and a status. The hook
  reads the end of that transcript (`sandboxblock::background`), only for a result that reads
  a background output file back: Claude Code's file tool on `<tasks>/<id>.output`, or a line
  of readers (`cat`, `tail`) naming one. The notification must name that output file by its
  whole path. Where any of Claude Code's own records for that task says `failed` (a task ends
  once), what was read is that command's own error, read as a failed command's is, and its
  socket is named. Only Claude Code's own records count, the queued notification and the
  message it becomes, never a tool's result that quotes one, and only a background command's,
  not a helper agent's. With no record (the command still runs) it is printed text, as before.
- **More readers count as running a program** (#2203): `rg` with `--pre`, `sort` with
  `--compress-program`, `less` and `more` (their input preprocessor, `LESSOPEN`, is a program
  the environment names), and `git` given configuration on its line (`-c`, `--config-env`,
  `GIT_CONFIG_*` in its environment: `diff.external`, `core.fsmonitor`), given
  `GIT_EXTERNAL_DIFF` or `--ext-diff`, or a `git grep` that opens its files in a pager (`-O`,
  `--open-files-in-pager`). A long option is read by any prefix the program itself accepts for
  it (`sort --compress`, `git grep --open-files`).
- **Codex's result has no status to read** (#2202). In Codex `rust-v0.147.0`, the version
  purlis's Codex support is read from, a shell command's `PostToolUse` `tool_response` is one
  string of what it printed (`handlers/shell.rs` through `format_exec_output_str`, which adds
  no exit code; the unified exec's `truncated_output`), and the payload has no exit code or
  status field (`hooks/src/events/post_tool_use.rs`). So a Codex result stays read by its line.
