# Amended 2026-11-02: a terminal runs the outcome evals it names

Ticket #4312, left from #3241. It replaces the last sentence of the third paragraph of the amendment
of 2026-10-31, "a grade can be asked for at a terminal", now that #3235 has landed, and every
limit of the outcome evals' own amendment holds: no shell in their chats, and a profile that signs
in through the person's settings refused in the plan and at start.

**`--eval <id>` runs exactly the evals it names.** The named ids reach `planned_with` as ticks do,
in the window's plan, in the window's start and in the terminal's own read, so the terminal prints
each as on or off, the digests still have to match, and the yes covers what was named. With none
named, no eval runs, as with none ticked.

**An id the plan would not run refuses the plan** (`grades::planned_named`), saying why: not a
number, not in the file, left out of the plan with its reason, or a file that does not read. A press
ticks only what the plan offered, but a terminal can name anything, and a plan holding less than was
named would take a yes for something else.

**A run naming an eval takes its yes typed at a terminal**: stdin and stdout both a terminal, and
`--yes` refused beside `--eval`. Each eval adds twelve or more of a whole turn's chats, where a
trigger test's chat ends once the skill starts. Such a run is refused before the host is asked. A
grade of trigger tests alone keeps `--yes` and a piped answer for a script, as it was.

**The window refuses a named eval on a profile it cannot run on before the yes is asked**: the plan
says why and consents to nothing, and the start takes the same check. A terminal's grade is
purlis's own runner, and `GradeOf` has no word for a Grader, so a Grader cannot stand beside named
evals.

**The plan says of an eval what a press sees**: its files and any character no reader would see.
**The scorecard printed at the end says each eval in each arm**, each expectation that failed and
why a run failed, and a grade stopped short says what stopped it, so a yes that spent on an eval is
answered there. A grade whose row could not be written prints no scorecard, as a step carries no
scores.

## Rejected

- **Dropping an id that does not parse or does not run, as the window's `ticked` does.** Its ticks
  come from the plan it showed; a terminal's come from a person's typing.
- **Refusing `--yes` for every grade.** The amendment of 2026-10-31 keeps it for a script, and a
  trigger-only grade's spend has not changed.
