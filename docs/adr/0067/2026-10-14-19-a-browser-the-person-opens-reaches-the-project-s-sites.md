# Amended 2026-10-14 (the operator's rulings on spec #2008, built in #2176): a browser the person opens reaches the project's sites and goes to an address they type

Under the rulings of 2026-10-14 (the person can open a browser with no chat; one grant system,
one Granted list; an address the agent writes for a site new to the project asks once), a browser
the person opens from the window is built as follows. It supersedes the last sentence of item 2
of the amendment *a browser's new sites are judged by its driver*.

1. **It reaches what the project's browsers reach.** It has no chat, so no chat's sandbox was
   compiled for it. It lists what the project's sandbox settings list for a chat on no persona,
   compiled as a chat's start compiles them (`purlis_core::sandbox::browser_listing`): the
   project's hosts, the hosts and services on this machine the person allowed for the project,
   and the hosts an administrator's policy pins as never allowed; and the browser sites allowed
   here. Never a persona's hosts, and never the floor's reach: whether or not the project turned
   the sandbox on, its settings are read as written, or as the defaults where it names none. A
   project whose file cannot be read lists nothing. *Decided in implementation, D-2176-1, to be
   confirmed.*
2. **It goes to an address the person types in its view tab**, in a field purlis draws outside
   the frame. Only an http or https address: any other scheme, an address with a name or
   password before its host, or one with a space, a control character or a backslash, is refused
   in words before anything is sent, and the engine refuses each again on its own. An address
   with no scheme is https, but a port of this machine written by its address
   (`127.0.0.1:5173`), which is http. An address the browser's reach refuses whatever the person
   answers (this machine but a port they allowed, a private or reserved address nothing lists, a
   name of this machine, a host policy never allows) is refused in the reach proxy's words
   before it loads. *Decided in implementation, D-2176-2, to be confirmed.*
3. **A site new to the project asks once**, as an address the agent writes does: the browser's
   judge holds it back, and the view asks under the field with the answers of a chat's sites ask
   in the same words, but for this chat, which a browser with no chat has none of: Always allow
   in this project, on this machine (a browser site of this project on this machine, listed in
   the Granted list); Allow for everyone in this project (a browser site committed to the
   project's settings, #2443), only where the project's sandbox is on, since only there does a
   committed browser site reach a browser; each unless an administrator's policy leaves its scope
   out; and Keep blocked. After an Allow the browser goes there. Where that address redirects
   while it loads is judged the same way. A public site on a port nothing lists asks too, for
   that host and port. *Decided in implementation, D-2176-3, to be confirmed.*
4. **The address goes on the browser's own lane**, after every key and click of the person's
   already sent. A browser the person drives is handed back first, and their next click or key
   takes it over again. A chat's browser has no address field: its chat drives it, and an
   address is sent only to a browser the window opened in that project. *Decided in
   implementation, D-2176-4, to be confirmed.*
5. **Each of the person's acts has an id of its own**, so the session host never answers one as
   a retry of another, a browser reattached after a crash of the window included. *Decided in
   implementation, D-2176-5, to be confirmed.*
