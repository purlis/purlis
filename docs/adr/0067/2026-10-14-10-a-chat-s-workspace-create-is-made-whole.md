# Amended (2026-10-14, qw387; amends section 2): a chat's workspace create is made whole — ruled by the operator, 2026-10-15

**Ruled by the operator, 2026-10-15.** Decided in implementation.

1. **Every form of `purlis workspace create` a chat runs is made by the app**, or refused before
   anything is made. A plain create and `--vision` are the brokered write they were. With repos
   named, the chat's command sends one git ask that names the new workspace, its vision and the
   repos; the app makes the workspace by the brokered create's own rules (a name that is not
   there yet, no link on the way, a folder it may write) and then clones the repos into it as
   `purlis clone` does for a chat, held to the chat's internet access. **A chat writes a
   workspace it does not work in only in the ask that makes it**: a later `purlis clone -w`
   naming that workspace is refused as for any other.
2. **What the app does not do for a chat is refused whole, in a sandboxed chat**, with the way
   to get it: `--live` (it changes the project's ignore file) and `--use` with its `--force` (it
   moves the chat into another workspace). A chat started without the sandbox runs them itself,
   as a terminal does.
3. **No maker of a workspace folder says it is ready over a write that failed.** A folder that
   could not be made is an error, nothing below it is tried, and a baseline path still missing
   after the scaffold, a vision or a share that could not be written fails `create`, naming them
   and `purlis workspace reinit`.
