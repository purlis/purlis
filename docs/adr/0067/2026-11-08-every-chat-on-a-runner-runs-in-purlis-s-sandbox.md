# Amended 2026-11-08: every chat on a runner runs in purlis's sandbox

Ruled by the operator on 2026-11-08. The amendment of 2026-10-30 held a Claude Code chat on a runner
to purlis's wrap; this holds every harness there to it.

1. **On a runner, no chat of any harness starts without the sandbox.** A Codex or opencode chat
   whose person chose "Start without the sandbox", whose own level is off, or whose floor could
   not be applied is refused in words by the runner's own start, as a Claude Code chat already
   was. So is a harness a project declares with no adapter, which nothing can sandbox yet: it
   runs on the person's own machine. The picker on a runner offers no way round it. A person's
   own machine is unchanged.
2. **A runner starts no harness from a window's own launch.** The window composes no chat for a
   runner; the runner composes each one, sandboxed. A launch by its words that names a harness is
   refused there; a shell is still the window's to start.
3. **The mark stays as a backstop.** A runner a chat ran on without the sandbox, or may have, is
   still marked, and starts no browser and is filled no login.
4. **The mark guards secrets, not code.** A marked runner is still sent a workspace's code and
   uncommitted work, as an unmarked one is: what the mark keeps from it is what a chat there must
   never reach, a browser, a login, a vault's value, a token or a sign-in.
5. **A pin is written in one spelling.** Each folder above a denied path is pinned by the
   spelling it has on disk. On a disk that compares names case-folded, a move by another spelling
   is matched as the folder is on disk, which `tools/seatbelt-case.sh` asserts for a pin on the
   macOS runner.
