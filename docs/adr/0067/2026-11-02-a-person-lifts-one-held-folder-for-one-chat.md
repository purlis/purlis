# Amended (2026-11-02, plane#2010's ruling): a person may lift one held folder for one chat

Ruled by the person, 2026-11-01 and 2026-11-02. This amends "Amended (2026-10-06): a block is never
a dead end", item 2, which keeps what later code loads out of every grant. A short list of later-code
names (`MAY_LIFT`) gets an Allow at the floor, because their owners write them in ordinary use:
`gh`, `glab` and `kubectl` settings.

- **One folder, named whole.** The Allow names that name below the home, and nothing else: not a
  copy elsewhere, and not a path reached through a link. Each start judges it again.
- **This chat alone.** It is a Write grant at the chat's level, never kept for every chat, and goes
  through the same audit.
- **At the floor alone.** The full sandbox keeps today's refusal, and a compile there ignores it.
- **Never** git's config, shell startup files, what the system starts at login, or a harness's or
  editor's own settings. `.claude/rules` is held with no Allow.
- **What it costs.** A chat with this Allow can leave code a later program runs outside any sandbox.
  The Notice says so. The Seatbelt profile holds every other copy of the name.
- **Only where one path can be named.** Chats under a Seatbelt profile get it. Claude Code's own
  sandbox can't name one path past a `denyWrite` glob, and a chat purlis wraps on Linux wasn't
  built, so both keep today's refusal.
