# Amended (2026-11-05): what a site's name and a field's origin are held to

Amends [A filled value reaches no string a chat reads](2026-11-05-a-filled-value-reaches-no-string-a-chat-reads.md).

- **A site asked about** is said unless its name holds something the browser keeps.
- **A field's origin**, which the window alone reads and compares, is held only to what purlis
  filled. What the person typed while driving takes no origin from a fill.
- **A text filled on a site doesn't hide that site**, or a site under it, where that site's name
  holds the text: the name says nothing of the text that it didn't say already. Every other site
  stays held to it. A site beside it, on the same registered name, stays held too: the engine
  keeps no list of registered names, and being strict there fails closed.
- **A string too much to read is said as blanked, whole**, since answers wait on reading it.
- **No fill goes to a host before 1.75**, nor a field read for one, whether a window or a relaying
  host would send it. 1.75 was chosen though v0.5.0 speaks 1.74: it is the floor a login has too,
  and 1.74 also covers builds from before these rules.
